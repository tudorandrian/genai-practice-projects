# P05 - K-Means + PCA Customer Segmentation

## What it does

An unsupervised segmentation pipeline: no labels are fed to the model. The
discipline is what matters - `StandardScaler` before any distance-based
clustering, k chosen on objective criteria (the elbow of inertia plus the
silhouette score) instead of guessed, a per-segment business profile via
`groupby`, and a PCA 2D projection with its explained variance reported so
the reader knows how much of the picture the plot actually keeps. The same
pipeline runs across six datasets - one synthetic set with a known ground
truth to validate against, and five public real datasets spanning retail,
wholesale distribution, urban transport, astronomy, wine chemistry and
handwriting - so the workflow is shown to be dataset-agnostic.

```
load_data -> preprocess (scale) -> choose_k (elbow+silhouette)
          -> fit_final -> segment_profile / validate_against_truth -> plot_* / pca_2d
```

`load_data(name)` returns a uniform `Dataset` container (unscaled numeric
features, domain, source, the k-search ceiling `k_max`, and an optional
`y_true`/`true_k` used only for post-hoc validation) for any of `customers`,
`wholesale`, `taxis`, `planets`, `winequality`, `digits`. `preprocess` scales
every feature to zero mean / unit variance and asserts the result actually
is standardized. `choose_k` fits K-Means for every k in `2..k_max`, records
inertia and silhouette, and returns the k that maximises the silhouette.
`run_one(name)` chains the whole pipeline for one dataset and writes its
metrics and two plots; `main()` and `demo()` are thin wrappers around it.

## Run

```bash
uv run p05-segmentation --demo                    # customers, offline, deterministic
uv run p05-segmentation --dataset customers        # default: the synthetic 3-segment set
uv run p05-segmentation --dataset wholesale         # a real segmentation set
uv run p05-segmentation --dataset all               # all six + comparison table
```

`--verbose` logs each pipeline step at `INFO`; by default only the summary
prints. Every run writes `elbow_silhouette<tag>.png`, `pca_segments<tag>.png`
and `metrics<tag>.txt` into `output/` for the dataset(s) it ran, where `<tag>`
defaults to `_<name>`; `--dataset all` additionally writes
`output/summary_all.txt` (a six-dataset comparison table, gitignored - it is
not the committed proof); `--demo` writes `output/metrics.txt` (compact
figures) and `output/summary.txt` (the one-row `customers` transcript)
directly from code, without shell redirection, so both files are
reproducible byte-for-byte.

### CLI flags

| Flag | Meaning | Default |
|------|---------|---------|
| `--dataset NAME` | Dataset to run: one of the six names, or `all` | `customers` |
| `--demo` | Run the offline demo (`customers`) | - |
| `--verbose` | Log pipeline steps at `INFO` | off |

## Design notes

- **Silhouette over inertia for choosing k.** Inertia falls monotonically as
  k grows, so it can only locate an "elbow" by eye; the silhouette score has
  a genuine maximum, so `choose_k` picks `argmax(silhouette)` and reports
  both curves side by side in `elbow_silhouette<tag>.png` for the reader to
  compare.
- **Ground truth is validation-only.** The synthetic `customers` set (and
  `wholesale`'s `Channel`, `winequality`'s `quality`, `digits`'s true label)
  carry a reference label, but it is stored on `Dataset.y_true` and never
  passed into `preprocess`, `choose_k` or `fit_final` - it is read back only
  by `validate_against_truth` (Adjusted Rand Index) after clustering, purely
  to check whether the unsupervised result agrees with a known answer.
- **Silhouette sampling on large sets.** `_silhouette` caps the sample at
  `SILHOUETTE_SAMPLE = 2000` rows (fixed `random_state`) once a dataset grows
  past that, since silhouette is O(n²); only `taxis` (6433 rows) is large
  enough to trigger the cap. `digits` (1797 rows) stays under the threshold
  and is scored exhaustively.
- **Download once, verify always.** `wholesale`, `taxis`, `planets` and
  `winequality` go through `shared.datasets.fetch(name, url, sha256)`, which
  caches the file under `GENAI_DATA_DIR` and re-verifies its SHA-256 on every
  call, raising `ChecksumError` on a mismatch instead of silently using a
  corrupted or tampered file. None of the four CSVs are committed to the
  repository. `customers` is a deterministic synthetic generator and `digits`
  ships inside scikit-learn - both stay fully offline.
- **`run_one(name, suffix="")` names files after the dataset by default.**
  With no `suffix`, the tag defaults to `_<name>` (`metrics_wholesale.txt`,
  `pca_segments_wholesale.png`, ...), so every dataset's outputs coexist in
  `output/` without collision, and `--dataset all` / `demo()` need no extra
  bookkeeping to avoid overwriting each other.
- **Output contract.** Library functions never `print`; they log through
  `logging.getLogger(__name__)`. `main()` prints at most six summary lines
  and sets the logging level (`WARNING`, or `INFO` with `--verbose`).
- **Determinism.** `RANDOM_STATE = 42` seeds every `KMeans`/`PCA`/silhouette
  sample and `DATA_SEED = 7` seeds the synthetic `customers` generator; two
  runs over the same dataset produce identical `best_k`, cluster labels and
  silhouette scores (see `test_two_runs_identical`, which compares all
  three). The committed proof files are the byte-level evidence: `--demo`
  regenerates them and leaves `git status` clean.

## Limits

- **Fixed feature sets per dataset.** Each dataset's clustered columns are
  hard-coded in `load_data`; there is no `--features` escape hatch to try a
  different subset without editing the module.
- **Silhouette-only k selection.** `choose_k` always maximises silhouette
  over `2..k_max`; there is no gap statistic, no BIC/AIC-style criterion, and
  no manual elbow override - the point is one clear, repeatable rule, not an
  exhaustive comparison of selection methods.
- **`digits`'s reported k is the search ceiling, not a peak.** Its silhouette
  keeps rising through `k_max=12` instead of turning over, so `argmax` lands
  on the last k searched rather than a genuine maximum; the true class count
  is 10. Raising `k_max` would very likely move the reported k further.
- **K-Means only.** No DBSCAN, no hierarchical or Gaussian-mixture
  clustering - the discipline demonstrated (scale, choose k objectively,
  profile, validate, project) applies to any of them, but only K-Means is
  implemented here.
- **`wholesale`/`taxis`/`planets`/`winequality` need a network connection the
  first time.** Their checksums (`DATASET_SOURCES`) are pinned to one
  specific upstream file each; if the upstream CSV is ever edited in place,
  `fetch` raises `ChecksumError` rather than silently using a different
  dataset.

## Datasets and licences

Six datasets for unsupervised clustering across six domains: one is a
deterministic synthetic generator written for this repository, one ships
with scikit-learn (fully offline), and four are fetched once through
`shared.datasets.fetch`.

| Key | Domain | Rows | Feat | Best k | Silhouette | Source & licence |
|-----|--------|-----:|-----:|-------:|-----------:|------------------|
| `customers` | retail | 360 | 3 | 3 | 0.664 | Synthetic 3-segment generator, written for this repository (fixed seed, no external data). **Primary / offline reference**, ground truth known |
| `wholesale` | wholesale distribution | 440 | 6 | 3 | 0.548 | [UCI Wholesale customers](https://archive.ics.uci.edu/dataset/292/wholesale+customers) (Cardoso 2014, CC-BY 4.0). Fetched once via `shared.datasets.fetch` and checksum-verified on every load; not committed |
| `taxis` | urban transport | 6433 | 6 | 2 | 0.707 | seaborn *taxis* (NYC TLC 2019) - public. Fetched once via `shared.datasets.fetch`; not committed |
| `planets` | astronomy | 498 | 4 | 2 | 0.418 | seaborn *planets* (NASA Exoplanet Archive) - public. Fetched once via `shared.datasets.fetch`; not committed (rows with NA in the four features dropped: 1035→498) |
| `winequality` | wine chemistry | 1599 | 11 | 2 | 0.214 | [UCI wine-quality-red](https://archive.ics.uci.edu/dataset/186/wine+quality) (Cortez et al. 2009, CC-BY 4.0). Fetched once via `shared.datasets.fetch`; not committed. `quality` held out as reference only |
| `digits` | imaging / handwriting | 1797 | 64 | 12 | 0.154 | `sklearn.datasets.load_digits` - UCI Optical Recognition (BSD-3); ships with scikit-learn |

**Feature selection per dataset:** `customers` clusters all three synthetic
features (`annual_income_k`, `spending_score`, `visits_per_month`); the
segment id that generated each row is kept as `y_true` for validation only.
`wholesale` clusters the six annual-spend columns (`Fresh`, `Milk`,
`Grocery`, `Frozen`, `Detergents_Paper`, `Delicassen`); `Channel` (Horeca vs
Retail) is dropped from training and kept only as a reference label.
`taxis` clusters six numeric trip columns (`passengers`, `distance`, `fare`,
`tip`, `tolls`, `total`); rows with any `NaN` among them are dropped.
`planets` clusters `orbital_period`, `mass`, `distance`, `year`; the
categorical `method` and the `number` index are dropped, and rows with `NaN`
in the four features are dropped. `winequality` clusters the 11
physicochemical features; the ordinal `quality` score is held out as
`y_true` only. `digits` clusters all 64 pixel intensities; the true digit
(0–9) is held out as `y_true`, and `preprocess` tolerates its always-zero
corner pixels (constant columns) instead of dividing by a zero standard
deviation. Each dataset remains under its own licence as listed above.
