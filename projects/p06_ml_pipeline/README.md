# P06 — ML Pipeline + Grid Search (Random Forest vs Logistic Regression)

## What it does

A production-shaped classification pipeline where the point is the *system*,
not a single model. Preprocessing (`StandardScaler` for numeric columns,
`OneHotEncoder` for categorical ones) and the classifier live inside **one**
`Pipeline`, tuned with `GridSearchCV` over a `StratifiedKFold(5)`. Two
models — Random Forest and Logistic Regression — are compared on the
**exact same preprocessing stack**, the second swapped in with a single
`set_params(clf=...)` so the comparison is honest: same folds, same
features, same metric. The winner is persisted with `joblib` and its
predictions are round-trip-verified after reload.

```
load_data -> build_pipeline -> stratified split
          -> tune_model(RF) -> tune_model(LR via set_params)
          -> evaluate (report + confusion) -> persist winner + round-trip
          -> write_metrics / write_model_card
```

`load_data(name)` returns a uniform `Dataset` container (raw numeric +
categorical features, the target, domain, source, an anti-leakage note, and
the minority "positive" class) for any of `weather`, `adult`, `credit_g`,
`churn`, `online_shoppers`, `bank_marketing`. `build_pipeline` wires a
`ColumnTransformer` and a classifier into one `Pipeline` so every
cross-validation fold fits its own preprocessing — nothing is ever fit on
held-out data. `run_one(name)` chains the whole pipeline for one dataset,
writes its metrics, a model card and four plots, and returns
`{"dataset", "winner", "f1", "roc_auc"}`; `main()` and `demo()` are thin
wrappers around it.

## Run

```bash
uv run p06-ml-pipeline --demo                    # weather, offline, deterministic
uv run p06-ml-pipeline --dataset weather          # default: the synthetic set
uv run p06-ml-pipeline --dataset adult            # a real census set
uv run p06-ml-pipeline --dataset all              # all six + comparison table
```

`--verbose` logs each pipeline step at `INFO`; by default only the summary
prints. Every run writes `metrics<tag>.txt`, `model_card<tag>.md`,
`model_best<tag>.joblib` and four plots (`01_confusion_rf<tag>.png`,
`02_rf_importances<tag>.png`, `03_confusion_lr<tag>.png`,
`04_lr_coefficients<tag>.png`) into `output/` for the dataset(s) it ran,
where `<tag>` defaults to `_<name>`; `--dataset all` additionally writes
`output/summary.txt` (a cross-dataset comparison table); `--demo` writes
`output/metrics.txt` (compact figures) and `output/summary.txt` (the
one-row `weather` transcript) directly from code, without shell
redirection, so both files are reproducible byte-for-byte.

### CLI flags

| Flag | Meaning | Default |
|------|---------|---------|
| `--dataset NAME` | Dataset to run: one of the six names, or `all` | `weather` |
| `--demo` | Run the offline demo (`weather`) | — |
| `--verbose` | Log pipeline steps at `INFO` | off |

## Design notes

- **The pipeline is the anti-leakage guarantee, not a convenience.** Fitting
  a scaler on all of `X` before the split would leak test statistics into
  training; putting the `ColumnTransformer` inside the `Pipeline` makes
  every CV fold fit its own preprocessing — structurally impossible to
  leak. For `weather` the target is additionally reframed so only
  information available *before* the prediction is used as a feature:
  `rain_yesterday` is a legal input, today's rain is the target only.
- **`set_params(clf=...)` keeps the comparison honest.** Two separate
  pipelines would let the preprocessing drift apart between the two
  candidates; swapping only the estimator guarantees Random Forest and
  Logistic Regression see identical features and folds — the one condition
  a model A/B must meet.
- **Accuracy picks the winner; the model card reports more.** `run_one`
  still picks the winner by test-set accuracy (matching the head-to-head
  table in `metrics<tag>.txt`), but `write_model_card` and the returned
  result also carry `f1` and `roc_auc` on the minority/event class, since
  accuracy alone is misleading on the imbalanced sets here.
- **Column types are auto-detected** with `select_dtypes` — numeric columns
  go to `StandardScaler`, everything else to
  `OneHotEncoder(handle_unknown="ignore")` — so the same code adapts to
  each dataset without edits.
- **Download once, verify always.** `online_shoppers` goes through
  `shared.datasets.fetch(name, url, sha256)`, which caches the file under
  `GENAI_DATA_DIR` and re-verifies its SHA-256 on every call. `adult`,
  `credit_g`, `churn` and `bank_marketing` come from
  `sklearn.datasets.fetch_openml`, which caches under scikit-learn's own
  data directory; none of the five real datasets are committed to the
  repository. `weather` is a deterministic synthetic generator and needs no
  network.
- **Sets larger than `SAMPLE_CAP` (8000 rows) are stratified-subsampled**
  with a fixed `random_state` so the full six-dataset run stays fast.
- **The persisted model round-trips.** `run_one` dumps the winning
  `Pipeline` with `joblib`, reloads it in the same run, and asserts its
  predictions match the in-memory model's — real evidence the pipeline is
  serialisable, not just claimed.
- **Output contract.** Library functions never `print`; they log through
  `logging.getLogger(__name__)`. `main()` prints at most six summary lines
  and sets the logging level (`WARNING`, or `INFO` with `--verbose`).
- **Determinism.** `RANDOM_STATE = 42` seeds the split, both classifiers and
  `CV = StratifiedKFold(5, shuffle=True, random_state=42)`; two runs over
  the same dataset produce byte-identical metrics (see `test_two_runs_identical`).

## Limits

- **Grid search is small by design.** `RF_GRID` (2×2) and `LR_GRID` (3×2)
  keep the full six-dataset run fast and deterministic; a wider search
  could change the winner on some datasets.
- **One held-out split, no repeated CV for the reported test score.**
  `GridSearchCV` itself cross-validates for model selection, but the final
  head-to-head numbers come from a single `train_test_split`
  (`test_size=0.2`) — there is no confidence interval around them.
- **Winner is picked by test accuracy only.** `f1`/`roc_auc` on the
  minority class are reported for context in the model card and metrics
  file, but they do not currently drive the winner decision — on a set
  where the two disagree, the reported winner may not be the model with
  the best minority recall.
- **`adult`, `credit_g`, `churn`, `online_shoppers` and `bank_marketing`
  need a network connection the first time.** `online_shoppers`' checksum
  is pinned to one specific upstream CSV; if it is ever edited in place,
  `fetch` raises `ChecksumError` rather than silently using a different
  file. The OpenML sets rely on scikit-learn's own cache and checksum
  handling.
- **Two classifiers only.** Random Forest and Logistic Regression cover a
  non-linear and a linear baseline; the honest-comparison discipline shown
  here (one pipeline, `set_params` swap, same folds) applies to any other
  scikit-learn classifier, but only these two are implemented.

## Datasets and licences

Six binary-classification datasets with mixed numeric + categorical columns
and mostly imbalanced targets — the shape the `ColumnTransformer`
(scale + one-hot) pipeline is built for. One is synthetic (offline,
deterministic); five are public real datasets.

| Key | Domain | Minority/event class | Source & licence |
|-----|--------|----------------------|-------------------|
| `weather` | meteorology | rain today = `Yes` | Synthetic weatherAUS-style generator, written for this repository (fixed seed, no external data). **Primary / offline reference** |
| `adult` | census / income | income `>50K` | [OpenML 1590](https://www.openml.org/d/1590) — UCI Adult (Kohavi 1996), public. Fetched via `fetch_openml`; not committed |
| `credit_g` | credit risk | credit `bad` | [OpenML 31](https://www.openml.org/d/31) — Statlog German Credit, public. Fetched via `fetch_openml`; not committed |
| `churn` | telecom | churned = `1` | [OpenML 40701](https://www.openml.org/d/40701) — telecom churn, public. Fetched via `fetch_openml`; not committed |
| `online_shoppers` | e-commerce | purchase = `True` | [UCI Online Shoppers Purchasing Intention](https://archive.ics.uci.edu/dataset/468) (Sakar 2018), CC-BY 4.0. Fetched once via `shared.datasets.fetch` and checksum-verified; not committed |
| `bank_marketing` | bank marketing | subscribe = `2` | [OpenML 1461](https://www.openml.org/d/1461) — UCI Bank Marketing (columns anonymised `V1`..`V16`), public. Fetched via `fetch_openml`; not committed |

**Anti-leakage per dataset:** `weather` reframes `RainToday -> RainYesterday`
(a legal feature) and keeps today's rain as the target only; the synthetic
generator follows the same rule. `adult` drops `fnlwgt` (a census sampling
weight, not a real predictor). `credit_g` uses application attributes only.
`churn` drops the unique `phone_number` id (it would explode the one-hot
and leak identity). `online_shoppers` and `bank_marketing` use
same-session/pre-outcome attributes only. Each dataset remains under its
own licence as listed above; sets larger than `SAMPLE_CAP` (8000 rows) are
stratified-subsampled with `random_state=42`, preserving class proportions.
