# P04 - Decision-Tree Drug Classifier

## What it does

An explainable decision-tree pipeline: the point is not raw accuracy but that
the drawn tree diagram *is* the model - "if Na/K > 15 -> DrugY" is not an
approximation of the model's behaviour, it is the model's behaviour. The
disciplined workflow around a plain `DecisionTreeClassifier` - one-hot
encoding of categorical columns, a *stratified* train/test split, a depth
comparison (max_depth 3 vs 4), and the tree exported as text rules - is shown
to be dataset-agnostic by running the exact same pipeline across six public
classification datasets, mixing numeric-only and mixed numeric+categorical
features, binary and multi-class targets.

```
load_data -> explore_data -> preprocess -> stratified_split
          -> train_tree -> evaluate -> plot_* / extract_rules -> predict_patient
```

`load_data(name)` returns a uniform `Dataset` container (raw features split
into `numeric`/`categorical`, target, domain, source) for any of `drug`,
`iris`, `wine`, `breast_cancer`, `penguins`, `titanic`. `preprocess` one-hot
encodes the categorical columns with `pd.get_dummies`; numeric columns pass
through unchanged. `run_one(name)` chains the whole pipeline for one dataset
and writes its metrics, rules and three plots; `main()` and `demo()` are thin
wrappers around it.

## Run

```bash
uv run p04-decision-tree --demo                  # drug + iris, offline, deterministic
uv run p04-decision-tree --dataset drug           # default: the synthetic drug set
uv run p04-decision-tree --dataset iris           # a numeric-only 3-class set
uv run p04-decision-tree --dataset all            # all six + comparison table
```

`--verbose` logs each pipeline step at `INFO`; by default only the summary
prints. Every run writes `metrics<tag>.txt`, `rules<tag>.txt`,
`decision_tree<tag>.png`, `class_distribution<tag>.png` and
`feature_importance<tag>.png` into `output/` for the dataset(s) it ran, where
`<tag>` defaults to `_<name>`; `--dataset all` additionally writes
`output/summary_all.txt` (a six-dataset comparison table, gitignored - it is
not the committed proof); `--demo` writes `output/metrics.txt` (compact
figures) and `output/summary.txt` (the drug + iris comparison table)
directly, without shell redirection, so both files are reproducible
byte-for-byte.

### CLI flags

| Flag | Meaning | Default |
|------|---------|---------|
| `--dataset NAME` | Dataset to run: one of the six names, or `all` | `drug` |
| `--demo` | Run the offline demo (drug + iris) | - |
| `--verbose` | Log pipeline steps at `INFO` | off |

`drug_acc: 1.000` is not an accident or an overfit number to be suspicious of:
`drug` is a synthetic generator written for this project (see "Datasets and
licences" below), and its rules are constructed to be exactly recoverable by
a tree of depth 4 - `test_synthetic_drug_is_perfectly_separable_at_depth4`

## Design notes

- **Explainability over accuracy.** The metric that matters is whether
  `extract_rules` (`sklearn.tree.export_text`) produces a rule set a human can
  read and apply by hand, not a marginal accuracy gain. `predict_patient`
  demonstrates this directly: it takes a raw profile dict, one-hot encodes and
  column-aligns it the same way training did, and returns the tree's
  recommendation.
- **The synthetic `drug` generator is retuned to be more class-balanced than
  a naive version.** An earlier version drew `Na_to_K` from one wide uniform
  range and split `BP` into equal thirds; that left `DrugB` (the rarest
  class, reached only through `BP == HIGH` and `Age > 50`) with about 14 of
  600 rows - too few for a stable test-set estimate. The shipped generator
  instead draws `Na_to_K` from two bands split around the 15 threshold (25%
  above, 75% below) and uses `BP` with `p=[0.3, 0.3, 0.4]`, which raises the
  actual class counts to `DrugY` 157, `DrugX` 131, `DrugC` 131, `DrugA` 114,
  `DrugB` 67 (`test_synthetic_drug_is_stable_and_balanced` floors every class
  at 60) - still the smallest, but no longer vanishingly so. The underlying
  rule thresholds are untouched, so `Na_to_K` remains the tree's dominant
  (root) split and highest-importance feature, exactly as intended.
- **One-hot alignment at predict time.** `pd.get_dummies` on a single new
  profile can produce a different (smaller) column set than training did - a
  profile with `BP="HIGH"` never produces a `BP_LOW` column. `_align_profile`
  reindexes the encoded row onto the trained feature columns, filling any
  missing dummy with 0, before `predict_patient` calls the model.
- **Depth 3 vs depth 4.** `run_one` always trains both and reports the
  accuracy delta; on the synthetic `drug` set both reach 1.0000 (the rule
  needs only three real decision points), while on other datasets a depth-4
  tree occasionally *loses* a little accuracy versus depth-3 (mild
  overfitting on a small test split) - the comparison is honest, not
  cherry-picked to always favour more depth.
- **Download once, verify always.** `penguins` and `titanic` are the only
  datasets fetched over the network; they go through
  `shared.datasets.fetch(name, url, sha256)`, which caches the file under
  `GENAI_DATA_DIR` and re-verifies its SHA-256 on every call, raising
  `ChecksumError` on a mismatch instead of silently using a corrupted or
  tampered file. Neither CSV is committed to the repository.
- **Output contract.** Library functions never `print`; they log through
  `logging.getLogger(__name__)`. `main()` prints at most six summary lines
  and sets the logging level (`WARNING`, or `INFO` with `--verbose`).
- **Determinism.** `RANDOM_STATE = 42` seeds both the synthetic generator and
  every split/model fit; two runs over the same dataset produce identical
  results - `test_two_runs_identical_accuracy` compares the in-memory accuracy
  of two fits, and `test_synthetic_drug_is_stable_and_balanced` pins the
  synthetic generator's own determinism.

## Limits

- **Fixed feature sets and a fixed one-hot scheme.** Each dataset's
  predictor columns are hard-coded in `load_data`; there is no `--features`
  escape hatch, and adding a new categorical value at predict time (a `BP`
  value the training data never saw) silently produces an all-zero dummy row
  rather than raising.
- **Only accuracy and a classification report.** No ROC/AUC, no confusion
  matrix, no per-class precision/recall plot - `evaluate` reports accuracy
  and `classification_report` text; deeper diagnostics are left to the
  metrics file's embedded `classification_report`.
- **Two fixed depths.** The depth comparison is hard-coded to 3 vs 4; there
  is no grid search or cross-validated depth selection, since the point is
  the discipline of comparing two honestly, not tuning for a leaderboard
  number.
- **`penguins`/`titanic` need a network connection the first time.** Their
  checksums (`DATASET_SOURCES`) are pinned to one specific upstream file
  each; if the upstream CSV is ever edited in place, `fetch` raises
  `ChecksumError` rather than silently using a different dataset.

## Datasets and licences

Six public classification datasets across five domains and three source
families: one is a deterministic synthetic generator written for this
repository, three ship with scikit-learn (fully offline), and two are
fetched once through `shared.datasets.fetch`.

| Key | Domain | Target | Rows | Feat | Acc (d4) | Source & licence |
|-----|--------|--------|-----:|-----:|--:|------------------|
| `drug` | pharmacology | `Drug` (5 classes) | 600 | 9 | 1.000 | Synthetic drug200-style generator, written for this repository (fixed seed, no external data) |
| `iris` | botany | `species` (3 classes) | 150 | 4 | 0.889 | `sklearn.datasets.load_iris` - Fisher (1936); ships with scikit-learn (BSD-3) |
| `wine` | chemistry | `cultivar` (3 classes) | 178 | 13 | 0.907 | `sklearn.datasets.load_wine` (UCI); ships with scikit-learn (BSD-3) |
| `breast_cancer` | oncology | `diagnosis` (2 classes) | 569 | 30 | 0.930 | `sklearn.datasets.load_breast_cancer` (WDBC, UCI); ships with scikit-learn (BSD-3) |
| `penguins` | biology | `species` (3 classes) | 333 | 9 | 0.950 | seaborn *palmerpenguins* (Gorman et al. 2014) - CC0. Fetched once via `shared.datasets.fetch` and checksum-verified on every load; not committed |
| `titanic` | history/survival | `survived` (2 classes) | 712 | 10 | 0.794 | seaborn *titanic* - no explicit licence upstream (redistributed via seaborn-data for teaching). Fetched once via `shared.datasets.fetch` and checksum-verified on every load; not committed |

**Feature selection per dataset:** `drug` uses `Age`, `Sex`, `BP`,
`Cholesterol`, `Na_to_K` (`Sex`/`BP`/`Cholesterol` one-hot encoded); `iris`,
`wine`, `breast_cancer` use every provided numeric feature as-is; `penguins`
uses `bill_length_mm`, `bill_depth_mm`, `flipper_length_mm`, `body_mass_g`
plus one-hot `island`/`sex` (rows missing any of those measurements or `sex`
dropped in one pass: 344->333); `titanic` uses `pclass`, `age`,
`sibsp`, `parch`, `fare` plus one-hot `sex`/`embarked` (rows with a missing
`age`, `embarked` or `survived` value dropped: 891->712). Each dataset
remains under its own licence as listed above. seaborn-data ships no licence
file of its own and disclaims being a general-purpose data archive; "no
explicit licence upstream" above means exactly that - not that the data is
dedicated to the public domain.
