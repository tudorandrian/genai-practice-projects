# P03 - Linear Regression Predictor

## What it does

A disciplined linear-regression pipeline run across seven public regression
datasets, to show that the workflow - not the one-line `LinearRegression().fit(...)`
call - is what matters: a correct train/test split, standardization fitted
**only on the training split** (no leakage into test), honest metrics on
unseen data, and coefficient interpretation instead of a bare score.

```
load_data -> explore_data -> preprocess -> train_model -> evaluate -> plot
```

`load_data(name)` returns a uniform `Dataset` container (features, target,
units, domain, source) for any of `diabetes`, `california`, `co2`, `mpg`,
`tips`, `diamonds`, `penguins`. `preprocess` splits first and fits
`StandardScaler` on the train split only, asserting the train columns come
out centred - a guard against accidental leakage. `run_one(name)` chains the
whole pipeline for one dataset and writes its metrics text file and
predicted-vs-actual scatter plot; `main()` and `demo()` are thin wrappers
around it.

## Run

```bash
uv run p03-regression --demo                  # tips + co2, offline, deterministic
uv run p03-regression --dataset co2           # default single dataset
uv run p03-regression --dataset diabetes      # offline reference (R2=0.453)
uv run p03-regression --dataset all           # all seven + comparison table
```

`--verbose` logs each pipeline step at `INFO`; by default only the summary
prints. Every run writes `metrics_<name>.txt` and
`predicted_vs_actual_<name>.png` into `output/` for the dataset(s) it ran;
`--dataset all` additionally writes `output/summary_all.txt` (a
seven-dataset comparison table, gitignored - it is not the committed proof);
`--demo` writes `output/metrics.txt` (compact figures) and
`output/summary.txt` (the tips + co2 comparison table) directly, without
shell redirection, so both files are reproducible byte-for-byte.

### CLI flags

| Flag | Meaning | Default |
|------|---------|---------|
| `--dataset NAME` | Dataset to run: one of the seven names, or `all` | `co2` |
| `--demo` | Run the offline demo (tips + co2) | - |
| `--verbose` | Log pipeline steps at `INFO` | off |

## Design notes

- **Anti-leakage order.** `preprocess` calls `train_test_split` before
  fitting `StandardScaler`, and fits the scaler on the train split only; it
  asserts the scaled train columns are centred (`< 1e-9`) as a runtime guard
  that a future refactor can't silently break.
- **Coefficients, not just a score.** `rank_coefficients` sorts the model's
  standardized coefficients by `|value|` descending, so `write_metrics`
  reports which feature actually drives the prediction, not only how well it
  fits.
- **Download once, verify always.** `diamonds` is the only dataset fetched
  over the network; it goes through `shared.datasets.fetch(name, url,
  sha256)`, which caches the file under `GENAI_DATA_DIR` and re-verifies its
  SHA-256 on every call, raising `ChecksumError` on a mismatch instead of
  silently using a corrupted or tampered file. `california` is downloaded and
  cached by scikit-learn itself on first use; every other dataset reads a
  small CSV committed under `data/`.
- **`run_one(name, suffix="")` names files after the dataset by default.**
  With no `suffix`, the tag defaults to `_<name>` (`metrics_tips.txt`,
  `predicted_vs_actual_co2.png`, ...), so every dataset's outputs coexist in
  `output/` without collision, and `--dataset all` / `demo()` need no extra
  bookkeeping to avoid overwriting each other.
- **Output contract.** Library functions never `print`; they log through
  `logging.getLogger(__name__)`. `main()` prints at most six summary lines
  and sets the logging level (`WARNING`, or `INFO` with `--verbose`).
- **Determinism.** `RANDOM_STATE = 42` is fixed for the split; two runs over
  the same dataset produce identical metrics (see `test_two_runs_identical_metrics`,
  which compares the in-memory MAE/MSE/RMSE/R2 of two fits).

## Limits

- **Fixed feature sets.** Each dataset's predictor columns are hard-coded in
  `load_data` (e.g. `co2`'s six numeric columns; categorical columns like
  `MAKE` or `cut` are dropped everywhere) - there is no `--features` escape
  hatch to try a different subset without editing the module.
- **Ordinary least squares only.** No regularization (Ridge/Lasso), no
  polynomial or interaction terms, no cross-validation - the point is the
  discipline around a plain linear fit, not model selection.
- **`diamonds` needs a network connection the first time.** Its checksum
  (`DATASET_SOURCES["diamonds"]`) is pinned to one specific upstream file;
  if the upstream CSV is ever edited in place, `fetch` raises `ChecksumError`
  rather than silently using a different dataset.

## Datasets and licences

Seven public regression datasets across seven domains and three source
families: two ship with scikit-learn (one fully offline, one downloaded and
cached by sklearn itself), four are small CSVs committed under `data/`, and
one (`diamonds`, the largest) is fetched once through `shared.datasets.fetch`.

| Key | Domain | Target [units] | Rows | Feat | R² | Source & licence |
|-----|--------|----------------|-----:|-----:|--:|------------------|
| `diabetes` | health | disease progression [index] | 442 | 10 | 0.453 | `sklearn.datasets.load_diabetes` - Efron et al. (2004); ships with scikit-learn (BSD-3). Offline reference |
| `california` | real-estate | median house value [$100k] | 20,640 | 8 | 0.576 | `sklearn.datasets.fetch_california_housing` - Pace & Barry (1997), StatLib; downloaded and cached by scikit-learn on first use |
| `co2` | automotive / emissions | CO₂ emissions [g/km] | 1,067 | 6 | 0.903 | Fuel consumption ratings - Government of Canada open data (Open Government Licence – Canada). Contains information licensed under the Open Government Licence – Canada. Committed at `data/FuelConsumptionCo2.csv` |
| `mpg` | automotive / efficiency | fuel economy [mpg] | 392 | 6 | 0.794 | UCI *Auto MPG* via [seaborn-data](https://github.com/mwaskom/seaborn-data) - no explicit licence upstream (redistributed via seaborn-data for teaching). | `tips` | dining / hospitality | tip [$] | 244 | 2 | 0.481 | seaborn *tips* (Bryant & Smith, 1995) - no explicit licence upstream (redistributed via seaborn-data for teaching). `data/tips.csv` |

**Feature selection per dataset:** `diabetes`/`california` use all provided
numeric features as-is; `co2` uses `ENGINESIZE`, `CYLINDERS`,
`FUELCONSUMPTION_CITY/_HWY/_COMB/_COMB_MPG` (categorical columns and the
constant `MODELYEAR` dropped); `mpg` uses `cylinders`, `displacement`,
`horsepower`, `weight`, `acceleration`, `model_year` (`origin`, `name`
dropped); `tips` uses `total_bill`, `size`; `diamonds` uses `carat`, `depth`,
`table`, `x`, `y`, `z`; `penguins` uses `bill_length_mm`, `bill_depth_mm`,
`flipper_length_mm`. Each dataset remains under its own licence as listed
above. seaborn-data ships no licence file of its own and disclaims being a
general-purpose data archive; "no explicit licence upstream" above means
exactly that - not that the data is dedicated to the public domain.
